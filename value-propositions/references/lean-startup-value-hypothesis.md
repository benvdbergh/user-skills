# Lean Startup — value hypothesis and validated learning

**When to load:** Early-stage offers, uncertain segments, innovation programs, or when the user wants to **test** whether a value proposition holds.

**Primary sources (external):** Eric Ries, *The Lean Startup*; Steve Blank’s customer development lineage; “build–measure–learn” as a learning loop. Official Lean Startup site principles: [Build–Measure–Learn](http://lean.st/principles/build-measure-learn).

## Core constructs

### Value hypothesis

A **value hypothesis** is a belief that:

- A defined customer segment
- Has a problem or job worth solving
- Enough that they will **adopt** and eventually **pay** (or sustain usage), given a specific offer

Treat it as falsifiable, not as a slogan.

### Minimum viable tests

Design the **smallest** artifact that tests the riskiest assumptions:

- Problem discovery (interviews, concierge)
- Solution simulation (prototype, wizard-of-oz)
- Willingness to pay signals (LOI, pilots, preorders—context-dependent)

## Agent practices

- Write hypotheses in **if / then / because** form when useful:

  > If **[segment]** experiences **[pain]** compared to **[NBA]**, then **[offer behavior]** will improve **[metric]**, because **[mechanism]**.

- Pair each hypothesis with:
  - **Metric or signal** (qualitative counts still count early)
  - **Falsifier** (what result would disprove it)
  - **Next experiment**

## No-gos

- Declaring product-market fit from anecdote
- Using MVP to mean “low quality” (MVP means **minimum to learn**, not minimum ethics)
