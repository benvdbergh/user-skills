# Organizational inputs and assumptions (mandatory gate)

**When to load:** Always first—before choosing frameworks, drafting, or critiquing a value proposition.

This gate ensures the agent knows **what evidence exists**, **who the proposition is for**, and **what reference scenario** (alternative, status quo) value is compared against. Without this, outputs drift into generic “sales pitch” language.

## 1. Purpose and scope

| Input | Why it matters |
|-------|----------------|
| **Goal of the exercise** | Design new VP vs critique existing vs test hypothesis vs align portfolio messaging |
| **Offering boundary** | Product, platform, service bundle, program, or company-level proposition (each implies different proof) |
| **Decision the VP must support** | Investment, purchase, adoption, internal prioritization—shapes depth of proof |

## 2. Audience and segment

Capture at least working definitions (refine later):

- **Primary audience**: Economic buyer, technical buyer, operator, partner, internal executive, board
- **Segment hypothesis**: Industry, geography, maturity, fleet size, regulatory intensity, integration complexity
- **Buying context**: New purchase, replacement, expansion, risk reduction, cost takeout, innovation mandate

**Assumption rule:** If segment is unknown, produce **segment variants** or label content “unsegmented hypothesis.”

## 3. Customer job and situation (JTBD-aligned)

- **Functional job** (what must get done)
- **Constraints** (time, cost, safety, uptime, compliance)
- **Social/emotional** pressures if relevant (career risk, reputation, team adoption)

**References to use after this section:** `jobs-to-be-done.md`, `value-proposition-canvas-osterwalder.md`

## 4. Competitive and alternative reference

Value is **relative**. Document:

- **Next-best alternative (NBA)**: Named competitor, in-house build, status quo process, or “do nothing”
- **Switching costs** and **migration risk** (often the real enemy in B2B)

**References:** `economic-value-and-pricing-logic.md`, `moore-positioning-statement.md`

## 5. Value mechanisms (how value is created)

List concrete mechanisms (not adjectives):

- Throughput, labor, energy, inventory, downtime, quality, risk, coordination cost, integration cost, training burden, time-to-recover, scalability

**References:** `bain-elements-of-value.md` for value type mix; `hbr-business-markets-value-propositions.md` for proof

## 6. Evidence inventory (what we can prove)

| Evidence type | Examples |
|---------------|----------|
| **Qualitative** | Interviews, win/loss, support themes, ethnography |
| **Quantitative** | Benchmarks, A/B, pilot KPIs, operational telemetry, ROI studies |
| **Third-party** | Analyst reports, certifications, audits (when allowed) |

**Gap handling:** If evidence is missing, mark claims as **hypothesis** and list the **minimum evidence** that would validate or falsify them.

**References:** `hbr-business-markets-value-propositions.md`, `lean-startup-value-hypothesis.md`

## 7. Constraints and non-goals

- Regulatory, safety, brand, channel conflicts
- What must **not** be promised (scope boundaries)

**Reference:** `skill-escalation.md`

## 8. Output contract

Agree on deliverable shape:

- Canvas bullets vs narrative paragraph vs slide-ready statements
- **Single segment** vs **matrix** (segment × value theme)

---

## Quick checklist (copy for sessions)

- [ ] Goal and offering boundary defined  
- [ ] Primary audience and segment hypothesis  
- [ ] Job + constraints + pressures  
- [ ] Next-best alternative named  
- [ ] Value mechanisms listed (not only adjectives)  
- [ ] Evidence inventory + gaps  
- [ ] Constraints and out-of-scope  
- [ ] Deliverable format agreed
