# Economic value logic — B2B “value in use” and alternatives (consulting practice)

**When to load:** Enterprise buyers, CFO scrutiny, procurement, ROI sections, or when the user asks for **quantified** or **economic** value stories.

This file summarizes widely used **consulting and pricing** concepts—especially **value relative to a reference alternative**—without reproducing proprietary firm methodologies verbatim.

## Core concepts (general industry practice)

### 1. Next-best alternative (NBA)

Customers implicitly compare your offer to:

- A named competitor
- **Status quo** / manual process
- **In-house build**
- **Do nothing** (often the strongest competitor)

**Rule:** If NBA is unclear, “value” is undefined.

### 2. Differential value (directional)

Articulate value as changes in:

- Revenue (throughput, service level)
- Cost (labor, energy, downtime, scrap, integration, training)
- Risk (incidents, security, compliance exposure)
- Capital efficiency (capex avoidance, asset utilization)

Prefer **mechanisms + direction** when hard numbers are unavailable.

### 3. Economic Value to Customer (EVC) — common label

Many pricing practices use an **EVC** style story:

\[
\text{EVC} \approx \text{Price of NBA} + \text{Differential value your offer provides vs NBA}
\]

Use this as **structuring logic**, not as a prompt to invent numbers.

### 4. Segmentation by value drivers

Customers differ in which **drivers** dominate (uptime vs labor vs risk). Messaging and proof should follow those drivers.

## Agent practices

- Build a **value driver tree**: outcome → mechanism → observable metric candidate.
- Separate **hard** effects (hours, downtime) from **soft** effects (anxiety, reputation)—mark soft items as hypothesis until supported.
- Always list **assumptions** behind any numeric illustration.

## No-gos

- Fabricated ROI percentages or currency savings
- Presenting illustrative arithmetic as audited customer results
