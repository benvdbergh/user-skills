# Repository Docs Audit Checklist

Use with `scripts/repo_docs_audit.py` and manual review.

## 1) README Quality

- [ ] README exists in one of: `.github/`, root, `docs/`
- [ ] First screen contains clear value proposition
- [ ] Quick start path exists and is runnable
- [ ] Links to `CONTRIBUTING.md`, `SECURITY.md`, `SUPPORT.md`, `LICENSE`
- [ ] Internal links are relative (where applicable)
- [ ] README not oversized for GitHub render (<=500 KiB)

## 2) Repository Metadata Discoverability

- [ ] "About" description communicates problem + audience
- [ ] Topics are relevant, specific, and <=20
- [ ] Social preview image is configured and legible
- [ ] Homepage URL points to live canonical docs/site (if used)

## 3) Docs Information Architecture

- [ ] README clearly points to deeper docs location
- [ ] `docs/` has index/landing page
- [ ] Docs separated by purpose (getting started/reference/operations/architecture)
- [ ] Wiki usage is intentional and non-duplicative (if enabled)

## 4) Community Health Baseline

- [ ] `LICENSE` present
- [ ] `CONTRIBUTING.md` present
- [ ] `CODE_OF_CONDUCT.md` present
- [ ] `SECURITY.md` present
- [ ] `SUPPORT.md` present
- [ ] Issue template(s) present in `.github/ISSUE_TEMPLATE/` (recommended)
- [ ] Pull request template present (recommended)

## 5) Freshness Signals

- [ ] Major docs contain "Last reviewed" dates
- [ ] Review cadence defined (for example 90-180 days by doc type)
- [ ] Stale docs list exists and has owners
