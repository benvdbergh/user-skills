# Repository Metadata Discoverability

## Goal

Improve first impression and searchability from repository "About" metadata.

## Description standard

Use a short plain-language description with:
- Problem solved
- Target user
- Current status or differentiator

Pattern:
`<What it is> for <who>, focused on <outcome>. <Maturity or notable trait>.`

## Topics standard

GitHub topics help users discover repositories by subject.

Rules:
- Use lowercase letters, numbers, and hyphens.
- Use <=50 chars per topic.
- Use <=20 topics total.
- Prefer specific domain and ecosystem topics over generic tags.
- Review topics quarterly and remove stale technology/version tags.

Topic mix recommendation:
- 2-4 domain topics
- 2-4 technology/runtime topics
- 1-2 architecture/pattern topics
- 1-2 community/use-case topics

## Social preview standard

Configure a custom social preview image to improve link unfurls.

Constraints:
- PNG, JPG, or GIF
- Under 1 MB
- At least 640x320 (1280x640 recommended)

Content guidance:
- Product/repo name
- Short claim (3-7 words)
- High contrast, readable at small size

## Audit checklist

- Description communicates problem + audience.
- Topics are relevant and not stale.
- Social preview exists and is legible.
- Homepage URL (if present) points to live docs/site.
- "About" metadata aligns with README first paragraph (no message drift).
