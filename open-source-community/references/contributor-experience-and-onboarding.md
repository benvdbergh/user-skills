# Contributor Experience And Onboarding

## Focus

This reference improves newcomer onboarding, early contribution success, and repeat participation.

## Friction-Reduction Strategy

Treat contribution as a pathway with explicit stages:
- discover project
- understand purpose and setup
- make first small contribution
- get timely feedback
- return as repeat contributor

Reduce friction at each stage.

## Onboarding Essentials

1. Friendly and actionable `README`
   - Project purpose, install/run steps, contribution links, and support channels.

2. Clear `CONTRIBUTING`
   - Local setup, coding and docs standards, test expectations, PR process.

3. First-contribution labels
   - Use labels such as `good first issue` with clear acceptance criteria.

4. Fast first response
   - Acknowledge issues and pull requests quickly to improve return probability.

5. Public communication channels
   - Keep non-sensitive support and decisions in public spaces to avoid private gatekeeping.

6. Contributor pathway visibility
   - Explain how casual contributors can become regular reviewers and maintainers.

## Interaction Norms For Maintainers

- Acknowledge effort first.
- Ask clarifying questions without blame.
- Tie feedback to documented standards.
- Close the loop with a clear next action.

## Metrics For Onboarding Quality

- Time to first maintainer response
- First PR acceptance ratio
- New contributors per period
- Repeat contributor rate
- Open issue age distribution

Use trend directions, not isolated values, to evaluate changes.
