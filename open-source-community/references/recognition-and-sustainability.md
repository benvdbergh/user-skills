# Recognition And Sustainability

## Focus

This reference covers recognition systems and operational safeguards that reduce maintainer overload and improve long-term continuity.

## Recognition Principles

- Recognize all contribution types, not only merged code.
- Make recognition visible, regular, and specific.
- Tie increased responsibility to demonstrated contribution and trust.

## Practical Recognition Patterns

1. Contributor acknowledgments
   - Maintain an AUTHORS or contributor section.
   - Use periodic shout-outs in release notes or community updates.

2. All-contributors style attribution
   - Include docs, design, triage, mentoring, moderation, and advocacy.

3. Pathway-based recognition
   - Define progression: contributor -> reviewer -> maintainer.
   - Clarify criteria and expected responsibilities at each stage.

## Sustainability And Burnout Safeguards

- Set public maintainer availability windows and response expectations.
- Rotate high-toil duties (triage, release chores, moderation, security review).
- Keep backup maintainers and emergency contacts.
- Use automation to reduce repetitive labor.
- Enable maintainers to pause without community ambiguity.

## Moderation Safety Baseline

- Adopt a code of conduct with explicit reporting routes.
- Define who handles reports and escalation alternatives.
- Document consistent enforcement and follow-through.

## Sustainability Metrics To Track

- Maintainer response time trend
- Review queue age
- Number of active maintainers by month
- Maintainer concentration risk (single-point ownership areas)
- Reopen rate caused by rushed review
