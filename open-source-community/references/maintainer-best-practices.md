# Maintainer Best Practices

## Focus

This reference covers maintainer operating patterns that protect project quality and maintainer capacity.

## Core Practices

1. Document vision and scope
   - Keep project goals visible in `README` or `VISION`.
   - Use scope statements to evaluate requests consistently.

2. Publish contribution expectations
   - Define response-time expectations.
   - Define acceptance criteria for pull requests.
   - Clarify what kinds of contributions are in and out of scope.

3. Keep decisions and support public by default
   - Route feature/support discussion to public issue and discussion channels.
   - Preserve decision records for newcomers and future maintainers.

4. Triage fast and close clearly
   - Acknowledge new issues quickly.
   - Close out-of-scope requests with a short, respectful explanation and links.
   - Avoid long-lived ambiguous backlog items.

5. Share ownership intentionally
   - Label beginner-friendly tasks.
   - Add repeat contributors to trusted responsibilities in stages.
   - Document path from contributor to maintainer.

6. Use automation for routine maintenance
   - Templates, CI checks, stale handling, and dependency automation reduce toil.
   - Keep automation rules visible to avoid perceived arbitrariness.

7. Prevent burnout as a first-class requirement
   - Set explicit availability boundaries.
   - Normalize maintainer pauses and handoffs.
   - Maintain at least one backup maintainer for continuity.

## Maintainer Communication Pattern

Use this short response structure for issue and PR interactions:

- Thank: appreciate the effort or report.
- Decision: accept, request changes, defer, or decline.
- Reason: tie decision to project scope or standards.
- Next step: exact action, alternative path, or closure rationale.

## Anti-Patterns

- Private decision-making on public roadmap topics.
- Unclear or moving acceptance criteria.
- Hidden maintainer expectations.
- Silent issue closure without context.
- A single maintainer acting as permanent gatekeeper with no succession path.
