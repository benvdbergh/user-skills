# Community Health Checklist

Use this checklist for monthly or quarterly community health reviews.

## A. Contributor Experience

- [ ] `README` gives clear purpose and quick-start steps.
- [ ] `CONTRIBUTING` covers setup, standards, and PR process.
- [ ] Beginner-friendly issue labels are used and maintained.
- [ ] First-time contributor guidance is explicit.
- [ ] Average time to first response is tracked.

## B. Governance Transparency

- [ ] `GOVERNANCE.md` exists and reflects current practice.
- [ ] Role definitions include authority and responsibilities.
- [ ] Decision process and tiebreaker are documented.
- [ ] Appeal or dispute path is documented.
- [ ] Leadership roster is up to date.

## C. Communication And Conduct

- [ ] Public support and decision channels are defined.
- [ ] Code of conduct exists and is linked from `README`.
- [ ] Reporting path includes an alternative contact.
- [ ] Moderation actions are documented consistently.
- [ ] Sensitive reports are handled privately and safely.

## D. Recognition And Inclusion

- [ ] Non-code contributions are recognized publicly.
- [ ] Contributor acknowledgments are updated regularly.
- [ ] Contributor progression path is visible.
- [ ] Repeat contributors receive expanded responsibility where appropriate.

## E. Sustainability And Burnout

- [ ] Maintainer availability boundaries are explicit.
- [ ] Rotations exist for high-toil tasks.
- [ ] Backup maintainers are identified.
- [ ] Automation reduces repetitive work.
- [ ] Maintainer pause or handoff protocol is documented.

## F. Metrics Snapshot (Minimal Set)

- [ ] New contributors per month
- [ ] Repeat contributor rate
- [ ] Time to first response
- [ ] Open issue age (median or p75)
- [ ] Pull request merge lead time
- [ ] Active maintainer count
