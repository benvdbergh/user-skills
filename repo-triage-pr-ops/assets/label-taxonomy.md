# Label Taxonomy

Use one label from each primary axis to keep triage deterministic.

## Type

- `type:bug`
- `type:feature`
- `type:docs`
- `type:question`
- `type:chore`

## Priority

- `priority:p0` critical outage, security, or data-loss risk
- `priority:p1` major user impact or regression
- `priority:p2` normal planned work
- `priority:p3` low urgency

## Status

- `status:triage-needed`
- `status:needs-info`
- `status:accepted`
- `status:in-progress`
- `status:blocked`
- `status:ready-for-review`
- `status:stale`

## Contribution Signals

- `good first issue`
- `help wanted`
- `duplicate`
- `invalid`
- `wontfix`

## Optional Area Axis

- `area:api`
- `area:web`
- `area:docs`
- `area:infra`
- `area:ci`

## Notes

- Apply only one `status:*` and one `priority:*` label at a time.
- Keep descriptions in repository settings aligned with this file.
- Reserve temporary labels (for example `needs-repro`) for maintainers only.
